# VC 机构筛选与案例归因

本期核查时点为 2026-10-30。资料用于了解团队、投资方向、案例和公开渠道，不预设个人求职偏好，也不进行基金收益排名。

## 分组与范围

- **2024–2026 新设机构**：优先成熟投资人离开原平台后成立的独立市场化机构。成立口径与团队来历应有可核对来源。
- **2020–2023 新一代机构**：补充已有数年独立运作记录、能观察新机构实际出手的团队，避免把六年前成立的基金称为“今年新成立”。
- **成熟机构**：选择有公开代表案例、明确投资策略和近期活动记录的机构，偏中国科技、AI 与硬科技，同时保留综合型和相关垂直领域的区别。

不把新一期基金、管理人登记、品牌更名自动等同新成立 VC；不将二级证券私募、CVC 或母基金硬塞进同一种 VC 定义。若机构跨 VC/成长投资、境内外投资或由原团队独立延续，应写清楚适用范围。

`coverage.role` 区分本期主要样本（`main`）、证据尚有限的观察补充（`watchlist`）和范围相邻的跨市场/全球华人机构（`adjacent`）。这是编辑层面的纳入范围，不是基金收益、投资价值或质量评级；具体原因保存在 `coverage.reason`。

## “有成绩”怎样记录

1. 先明确是谁在什么机构期间做的项目：个人、团队和机构三个层级不能互相替换。
2. `prior_firm` 只证明创始人或团队的历史履历，不能归为新机构业绩；`current_firm` 才是当前机构的投资案例。
3. 知名公司、IPO、后续融资和已实现退出各自分开。不凭融资额或估值推断 IRR、DPI、出资回报或已回收现金。
4. 新 GP 可能只有早期出手，还没有成熟退出周期；没有找到新机构独立案例时保留这一缺口，不因此编造表现。
5. 近期活跃度优先参考有日期的投资、募资、退出或组织公告。官网存在、参会发言或过去案例本身不足以证明近期持续投资。

## 字段和来源

机构 JSON 契约见 [investor.schema.json](../schemas/investor.schema.json)。`why_follow` 和 `difference` 属于编辑分析，应该落在团队能力、投资阶段、赛道或资源上的具体区别，不能写成未经测量的“更强”“回报更好”。

`representative_cases[].evidence_source_ids` 必须对应本机构的 `sources[].id`，每个来源说明支持的事实。优先官网、投资公告、被投企业、监管披露；用可靠媒体补充时注明报道性质及其限制。未公开邮箱用 `null`；BP/融资项目邮箱、一般商务邮箱与招聘邮箱分别记录。

Agent 入口：[机构机器索引](../data/investor-index.json)。阅读版：[机构目录](../catalog/investors/README.md)。原始数据只维护在 `data/investors/`，再运行生成和校验命令。
